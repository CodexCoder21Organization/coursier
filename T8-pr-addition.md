
The user requested “add permanent large-body streaming tests to coursier PR 8, then push” after RC8 found that its large-body probes were only temporary. This addition keeps three 4 MiB real-loopback tests in `DownloadEncodingIntegrityTests`: `large gzip body streams into the cache before the remainder arrives`, `large deflate body streams into the cache before the remainder arrives`, and `large multi-member gzip streams inside a later member before the remainder arrives`.

Each server withholds the second half until FileCache has reported 2 MiB of decoded progress and the test has checked the exact temporary-file prefix with no final cache file published. The multi-member case pauses inside its second member. The final cache bytes must match the complete generated body, cumulative progress must increase strictly to the decoded length, and the request/completion counts and temporary-file removal are checked. This guards against whole-body or whole-member buffering before progress through public callbacks and files; it does not claim a measured heap bound. Progress-total behavior remains unchanged.

T8 validation: all three tests fail once each when a temporary whole-body decoded buffer is inserted before copying; that mutation was restored and is absent from the product branch. Each restored test passes 30/30, followed sequentially by framing 103/103 and cache module 214/214. These are 407 passing first attempts, zero retries/errors/skips, with at most two observed JVMs. The cache module uses the same `testLocal` approach as the prior gate. Existing test/assertion edits in T8: none; only one new helper and three new test bodies were added. Tests, mutation patch, per-attempt XML/events and review evidence are recorded in [T8 findings](https://github.com/CodexCoder21Organization/coursier/blob/wip/T8-evidence-20261023/findings.md).
