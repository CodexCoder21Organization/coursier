# T8 dedicated review passes

## Test comprehensiveness pass
Read current DocumentationRepository PHILOSOPHY.md and architecture/TESTING.md, coursier README.md and DEVELOP.md, RC8 review.md/Rc8StreamingTests.scala, the existing DownloadEncodingIntegrityTests harness, and Downloader's decode/copy path.

The new coverage targets public FileCache downloads and callbacks through actual ephemeral loopback TCP servers. Each case has a 4 MiB seeded random decoded body, so both decoded and encoded traffic are multi-megabyte. The gzip and deflate controls pause inside a sync-flushed stream; multi-member gzip sends one complete 1 MiB member and pauses halfway through the next 3 MiB member. A decoder buffering either the entire body or the entire current member cannot reach the required 2 MiB progress position before the server sends the remainder.

The existing harness asserts that the download is incomplete while paused and snapshots public cache paths before releasing the server. New assertions check final absence, temporary presence, exact 2 MiB prefix bytes, exact final 4 MiB cached bytes, temporary-file removal, one request and one successful completion. Cumulative callback positions must increase strictly and end at the decoded length. No comparison with the compressed total is added. A fixed seed makes input repeatable without reading environment state; directories, sockets and executors are owned and removed by the existing scenario's finally blocks.

These tests close the requested scale/progress gap. They do not assert a precise retained-heap bound or rule out every buffering strategy after a callback has been reported. The withheld-remainder handshake is the public behavioral guard requested in the brief; no reflection or JVM flags are needed. Existing corruption, incomplete framing and trailer checks remain covered by the original suites and final framing/module gates.

## Separate code review pass
The product diff only adds one private helper and three named tests in the existing suite. Existing cases, assertions, waits and iteration counts are unchanged. No shared interface or production path changes, new public methods, reflection, mocks, retries, sleeps or conditional skips are introduced. ByteArrayOutputStream can be reused after close; each compressor owns no external resource and is closed after encoding. Generated byte arrays are finite and the comparison avoids converting multi-megabyte arrays to boxed Scala sequences. The existing harness closes streams, sockets, executors and its isolated temporary directory even when the handshake fails.

README already documents the incremental decoded-progress contract, so no README edit is needed for permanent tests of existing behavior. The final diff must contain no mutation or generated build output. Mutation and gate results will be recorded separately before relying on the result.
