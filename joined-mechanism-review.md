## Inference and limits

The forced run demonstrates this sequence: the receiver’s accept expires before the callback returns; the late child connection succeeds at the listening socket but receives no reply; the child remains blocked reading that reply; and the synchronous parent call does not finish before its outer test deadline. The independent 10/10 loopback trials support the receiver-expiry/late-connection behavior, while the 20/25-second child frames show the blocked read in the full diagnostic.

This is a matching, deliberately forced mechanism, not conclusive recovery of the original gate failures’ cause. In the original test the callback returned before the accept future expired, and those failures never recorded the future’s `SocketTimeoutException`. The existing gate therefore does not prove that the same ordering occurred there. No buffer or host cause follows from this evidence.
